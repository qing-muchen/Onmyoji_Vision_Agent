# Phase 11.5 — yard 数据审计与模板利用改进报告

> 目标：**不重新采集任何截图**，审计并利用现有 ``dataset/raw/yard``，判断"庭院判断样本过少"
> 究竟是**原始数据不足**还是**数据利用不足**；再依据实测证据决定是否修改 detector。
>
> 不得：复制图片凑数 / 把 ``features``·``states`` 派生图当独立原图 / 降阈值但不报误报 /
> 引入 YOLO / 修改真实输入安全设置。

---

## 0. 一句话结论（先读）

**现有 dataset 不缺 yard 样本，是 yard 数据利用不足。**

| 事实 | 实测 |
| --- | --- |
| ``raw/yard`` 原图 | **98 张**（SHA256 去重 98，精确重复 **0**） |
| 可辨识皮肤/UI 变体 | **18 种**（``cap`` 28 张 + ``skin001…skin018`` 70 张） |
| 有效视觉多样性 | dHash 聚类 **57 组**（近重复 53 对**全部是同皮肤内部**，跨皮肤 **0** 对） |
| 当前证据用了几张模板 | 模板目录 **28** 张 → 配置只加载 **8** 张，且 **28 张全部来自 ``cap``** |
| 皮肤覆盖 | **18 种皮肤 0 覆盖**（70 张原图从未进入模板库） |
| 当前配置真实能力 | 98 张里只有 **8 张**判为 yard，**这 8 张恰好是被抽样的 8 张模板源图**（自匹配）；留一法(LOO)泛化 **0/98** |
| 误报 | 负样本 80 张 → **FP 0**、证据假命中 **0**（阈值 0.85 并不过松） |
| 阈值是否瓶颈 | **不是**：降阈值收益远小于补覆盖（见 §6） |
| 真正瓶颈 | **模板覆盖面（尤其皮肤）** + **单一证据**（无 OCR 锚点、无负样本判别、150 张负样本素材未用） |

据此做了**最小、可复现**的利用改进（不新增图片、不改阈值）：
``max_templates: 8 → 16`` + 新增 ``dedupe_threshold: 6``（近重复模板去重）。
复测：**TP 8 → 21**、LOO 泛化 **0/98 → 9/98**、负样本 **FP 仍 0/80**，
代价是 yard detector 单项耗时 **111ms → 218ms**（见 §8）。

## 1. 审计方法与口径（只读）

新增 ``tools/audit_yard_dataset.py``（**只读**：不改 ``configs/``、不改 ``dataset/``、不发任何输入）：

```bash
python tools/audit_yard_dataset.py                      # 数据构成 + 现有识别链 benchmark + 策略/皮肤实验
python tools/audit_yard_dataset.py --skip-detection     # 只做数据构成审计
python tools/audit_yard_dataset.py --skip-strategy-experiment
```

关键口径：

* **独立原图** = ``raw/`` 下的文件（按 SHA256 去重）；``features/`` ``states/`` ``scenes/`` 一律
  标为**派生**，单独统计，**不计数**为样本；
* **近重复** = 8×8 dHash 汉明距离 ≤ 6（与 Phase 11.3 审核包、Phase 11.5 模板去重同口径）；
  只**分组报告**，从不删除/合并；
* **留一法（LOO）** = 评估某张原图时，**排除由它自己派生的模板**。否则"用自己匹配自己"
  必然 1.0，会把覆盖不足掩盖成"模板够用"（这属于数据泄漏）；
* **低置信度** 在当前配置下**不可能出现**：detector 阈值 0.85 == 运行时稳定化阈值 0.85，
  且 yard 规则只要求 ``bottom_menu_yard``（``min_confidence=0.6``）⇒ 证据命中即状态 yard。
  因此本报告把 yard 正样本分为 **库内命中（含自匹配）** 与 **LOO 泛化命中** 两栏，而不是
  人为制造"低置信度"档。

## 5. 是"缺样本"还是"利用不足"？逐项排除

| 假设 | 实测证据 | 判定 |
| --- | --- | --- |
| 样本数量不够 | 98 张原图 / 57 个视觉组 / 零重复，且还有 150 张负样本 + 70 张场景图 | ❌ 不成立 |
| 多样性不够 | 18 种皮肤，跨皮肤近重复 **0** 对 ⇒ 变体确实不同 | ❌ 不成立 |
| 靠复制凑数就能变好 | 精确重复 0；派生图已单独隔离 | 不需要，也不允许 |
| 阈值太高 | 见 §6：降到 0.75 只多拿 13 个命中，而补皮肤模板可多拿 35+ | ❌ 不是主因 |
| **模板只用了 8/28 张，且 28 张全来自 cap** | 见 §4：库内命中恰为模板自身，LOO 泛化 0 | ✅ 主因之一 |
| **18 种皮肤 0 模板覆盖** | 见 §7 皮肤预估：每皮肤 1 张模板即可把 LOO 泛化从 9 提到 44 | ✅ 主因之二 |
| **证据单一**（无 OCR / 无负样本判别） | 单模板证据的泛化天然脆弱；150 张负样本素材闲置 | ✅ 结构性风险 |

**判定：数据利用不足。**（现有数据足够支撑更高的 yard 覆盖，问题在"用哪些模板、用几条证据"。）

## 6. 阈值扫描（生产模板集 / 模板库全量，均为 LOO）

| 阈值 | 生产模板集(16 张) 正/负命中 | 模板库全量 正/负命中 |
| --- | --- | --- |
| 0.60 | 41/98 、 6/80 | 50/98 、 6/80 |
| 0.70 | 30/98 、 4/80 | 39/98 、 4/80 |
| 0.75 | 22/98 、 **0/80** | 32/98 、 **0/80** |
| 0.80 | 13/98 、 0/80 | 22/98 、 0/80 |
| **0.85（现行）** | **9/98** 、 0/80 | 11/98 、 0/80 |
| 0.90 | 2/98 、 0/80 | 4/98 、 0/80 |

* 降阈值**确实**能在现有负样本上不引入误报（0.75 时负样本仍 0/80），但收益有限
  （9 → 22），且**没有**报错余量可言 —— 一旦真实环境出现"更像庭院"的界面，0.75 会开始误报；
* **本阶段没有下调阈值**（保持 0.85），因为改模板覆盖的收益更大且更安全。

**最像 yard 的负样本（模板库全量 LOO）**：

| 图片 | 原始分 | 状态 | 证据假命中 |
| --- | --- | --- | --- |
| ``raw/unknown/friends/unknown_friends_001.png`` | 0.7405 | unknown | 否 |
| ``raw/unknown/friends/unknown_friends_002.png`` | 0.7405 | unknown | 否 |
| ``raw/unknown/shop/unknown_shop_004.png`` | 0.7163 | unknown | 否 |
| ``raw/unknown/other/unknown_other_019.png`` | 0.7075 | unknown | 否 |
| ``raw/unknown/other/unknown_other_010.png`` | 0.6795 | unknown | 否 |

⇒ 最高 0.74 < 0.85，**0.85 在现有负样本集上并不过松**；`exploration`（36 张，与 yard 同有底部功能栏）
的最高原始分仅 0.545，说明"探索型功能栏"不会被误认为庭院。

## 7. 模板选择策略与皮肤模板收益（内存实验，不落盘）

### 7.1 策略对照（证据级；同一进程同一批次测量，耗时可横向比较）

| 策略 | 加载 | 来源数 | 库内命中 | **LOO 泛化** | 负样本假命中 | yard 单项耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| ``current``（8 张，不去重） | 8 | 1 | 8/98 | **0/98** | 0/80 | **111ms** |
| ``all``（28 张，不去重） | 28 | 1 | 32/98 | 11/98 | 0/80 | 384ms |
| ``dedupe6``（28 张上限，去重） | 25 | 1 | 30/98 | 11/98 | 0/80 | 375ms |
| **``dedupe6``（16 张上限）← 采用** | 16 | 1 | 21/98 | 9/98 | 0/80 | **218ms** |
| ``dedupe6 + per_source=4`` | 4 | 1 | 5/98 | 1/98 | 0/80 | 48ms |

要点：

* 28 张全量比 16 张只多 2 个 LOO 命中，却多花 **166ms**（整链会逼近 500ms 节拍）；
* ``per_source_limit`` 在当前**只有 cap 一个来源**时反而把唯一来源裁掉（4 张 → LOO 1/98），
  因此**本阶段不启用**，待皮肤模板入库后再用。

### 7.2 皮肤模板收益预估（**内存合成，未在 dataset 落盘**）

| 方案 | 合成 | 模板库 | LOO 泛化 | 负样本假命中 | yard 单项耗时 |
| --- | --- | --- | --- | --- | --- |
| 现状（仅 cap，16 张） | 0 | 16 | 9/98 | 0/80 | 218ms |
| 仅 cap 全量（28 张） | 0 | 28 | 11/98 | 0/80 | 384ms |
| **每皮肤 1 张** | 18 | 43 | **44/98** | **0/80** | 647ms |
| **每皮肤 2 张** | 36 | 61 | **61/98** | **0/80** | 986ms |

⇒ **天花板在皮肤覆盖**：仅靠 cap 模板最多 11/98；把**已经存在**的 70 张皮肤原图做成模板，
LOO 泛化可到 44~61/98，且负样本**依然 0 误报**。
但生成皮肤模板属于**数据生产**（新增派生文件），本阶段按你的决定**不落盘**，只给出量化收益。
